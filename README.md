# Speech Brain-Machine Interface Decoding: Gated Recurrent Unit vs. Transformer
Comparing a recurrent (GRU) decoder and a custom transformer decoder for an intracortical speech brain-computer interface, trained on the Brain-to-Text '25 data.

## Pipeline

<img width="2092" height="752" alt="image" src="https://github.com/user-attachments/assets/1157d0f6-c0aa-42b9-a4b2-3a667a942c0c" />



Neural features (512 per 20 ms bin) are split into overlapping patches of 14 bins with stride 4, passed through the model, and trained with CTC loss to predict a phoneme sequence.


## Summary

| Model | Params | Best val PER | Training |
|---|---|---|---|
| GRU (official architecture) | 44.3M | **13.43%** | 12,000 batches, batch size 32 |
| Transformer, lr 2e-3 | 21.7M | 41.79% | 12,000 batches, batch size 32 |
| Transformer, lr 1e-3 | 21.7M | 52.61% | 12,000 batches, batch size 32 |

For reference, the official pretrained GRU (120,000 batches, batch size 64) reports 10.1% PER.

**Main finding:** under a short (12k-batch, single T4) training budget, the GRU decoder clearly beats my transformer. The transformer was still underfitting (training CTC loss 18–30 vs. 3–5 for the GRU), and doubling its learning rate cut PER from 52.6% to 41.8%. I did not test whether a longer schedule would close the gap.

All numbers are phoneme error rate (PER) on the validation set with greedy CTC decoding and no language model. They are **not** comparable to the word error rates (WER) on the competition leaderboard.

Full run-by-run details are in [results.md](results.md).

## Background

Speech neuroprostheses record neural activity from the brain's speech motor areas and decode it into text, with the goal of restoring communication to people who have lost the ability to speak. This project uses the data from:

> Card et al., *An Accurate and Rapidly Calibrating Speech Neuroprosthesis*, New England Journal of Medicine, 2024. [PubMed](https://pubmed.ncbi.nlm.nih.gov/39141853/)
>
> <img width="1050" height="376" alt="image" src="https://github.com/user-attachments/assets/ddef14a5-fd2c-41a5-949d-199bc930a595" />


The dataset (intracortical Utah-array recordings, 45 sessions, 10,948 trials, 41 phoneme classes including blank) is available on [Dryad](https://doi.org/10.5061/dryad.dncjsxm85), and the baseline code is in the [official repository](https://github.com/Neuroprosthetics-Lab/nejm-brain-to-text). The paper's figures are not reproduced here; see the paper itself.

## Models

| | GRU (baseline) | Transformer (mine) |
|---|---|---|
| Parameters | 44,315,177 | 21,686,825 |
| Core | 5-layer GRU, 768 units | 4-layer encoder, d_model 384, 6 heads, FF 1536 |
| Input | Per-day 512×512 layers | Shared across days |
| Positions | n/a | Sinusoidal |
| Regularization | Official settings | Dropout 0.1, input dropout 0.2 |

The transformer plugs into the official training loop through a small patch (`train/transformer_trainer.patch`, applied at official commit `980a5b7`), so none of the official code is copied into this repo. See [train/README.md](train/README.md).

## Findings

- **GRU wins at this budget.** 13.43% vs. 41.79% for the best transformer.
- **The transformer underfits.** Its training loss stays far above the GRU's, so the gap is likely an optimization/budget issue rather than overfitting.
- **Learning rate mattered a lot.** 1e-3 to 2e-3 improved PER by about 11 points; higher rates were not tried.

## Limitations

- Short runs (12k batches vs. the official 120k) and half the official batch size.
- One seed per configuration, so small differences should not be over-read.
- Greedy decoding only; no language model, so no WER.
- The transformer differs from the GRU in more than architecture (e.g. weight decay applies to its encoder biases and LayerNorm); see [results.md](results.md).

## Ideas not yet tried

These are untested ideas, not results:

- Longer training for both models
- A convolutional front end before the transformer
- Further learning-rate tuning

## Reproducing

1. Download the dataset from Dryad and clone the official repo (see links above).
2. Apply `train/transformer_trainer.patch` as described in [train/README.md](train/README.md).
3. Run the notebooks in `notebooks/` in order (training notebooks were run on Kaggle).
4. Run `notebooks/05_results_figures.ipynb` to regenerate the figures from `logs/`.
